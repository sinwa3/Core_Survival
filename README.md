# 코어 서바이벌 (Core Survival)

**3D 탑다운 아레나 서바이벌 — 최대 89마리의 적과 스킬 이펙트, 데미지 숫자, 투사체를 오브젝트 풀 4종으로 돌려씁니다**

사방에서 몰려오는 적을 자동 공격으로 처치하며 버티는 게임입니다.
플레이어가 조작하는 것은 이동과 대시 회피뿐이고, 레벨업마다 뜨는 세 개의 선택지가 그 판의 빌드를 만듭니다.

## 이 프로젝트에서 볼 것 세 가지

### 1. 오브젝트 풀 4종 — 대상의 성질에 맞춰 정책을 따로 정했습니다

| | `EnemyPooling` | `SkillEffectPooling` | `DamageTextPooling` | `EnemyAttackPooling` |
|---|---|---|---|---|
| 대상 | 근접 · 원거리 적 | 스킬 이펙트 5종 | 데미지 숫자 | 원거리 적의 투사체 |
| 자료구조 | `Queue` + 활성 `List` | `Dictionary<SkillID, Queue>` | `Queue` + 활성 `Queue` | `Queue` |
| 상태 수 | **셋** (활성 / 시체 / 큐) | 둘 | 둘 | 둘 |
| 반환 | **2단계** (사망 연출 0.9초) | 1단계 | 1단계 + **강제 회수** | 1단계 |
| 큐가 비면 | 새로 만든다 | 새로 만든다 | **가장 오래된 것을 회수한다** | 새로 만든다 |
| 프리웜 | 근접 120 · 원거리 30 | 없음 | 40 | 50 |

적 풀은 같은 클래스의 인스턴스를 근접용과 원거리용으로 둘 둡니다.
스포너가 풀의 활성 개수를 보고 유지 마릿수를 채우기 때문에, 한 풀에 두 종류를 섞으면 원거리 적이 나오지 않습니다.

데미지 숫자 풀만 고갈 정책이 반대입니다. 프리웜 개수가 곧 화면 표시 상한이 되어 런타임 `Instantiate`가 구조적으로 0입니다.
적이 안 나오면 게임이 깨지지만 숫자 하나가 조금 일찍 사라지는 것은 알아차리기 어렵기 때문입니다.

### 2. 확장할 때 고친 곳을 세어 구조를 확인했습니다

| 확장 | 고친 곳 | 안 고친 곳 |
|---|---|---|
| 스킬 2종 추가 (미사일, 궤도 구체) | `SkillID` enum, `CreateSkill`의 `switch` — **2곳** | 풀, HUD, 선택지 패널 |
| 스킬 강화 선택지 신설 | 새 선택지 클래스 1개 + 에셋 | 선택지 패널 **0줄** |
| 쿨타임 강화 추가 | 기존 선택지 클래스에 필드 1개 | 선택지 패널 · 버튼 **0줄** |
| 치명타 추가 | 데미지 계산 메서드 1곳, 스탯 enum 값 1개 | 이펙트 5종, 데미지를 넣는 4곳 **0줄** |
| 선택지 리롤 | 선택지 패널 **파일 1개** | 선택지 클래스, 에셋, 스킬 매니저 |
| 원거리 적 추가 | 적 클래스에 공격 타입 enum과 타격 분기, 투사체와 투사체 풀 신규, 적 풀에 생성 시 투사체 풀 주입 | 스킬 5종, 스포너, 적 풀의 꺼내기 · 반환 코드 |

레벨업 선택지는 6개에서 19개까지 늘었지만 선택지 패널에는 종류 분기가 없습니다.

### 3. 측정하고 결과를 그대로 적었습니다

같은 빌드에서 풀링을 켜고 끄며 A/B로 쟀습니다.

| 측정 조건 | |
|---|---|
| 빌드 · 도구 | Development Build, Unity Profiler, Profile Analyzer |
| 적 수 | **90마리 고정** (원거리 적 추가 전에 측정. 추가하며 근접 75 + 원거리 14로 총합을 맞췄습니다) |
| 스킬 | 시작 스킬 1종 (5종 습득 조건에서도 결론이 같았습니다) |
| VSync | 켜짐 (60Hz, 프레임 예산 16.6 ms) |
| 길이 | 조건당 40~50초 |

| | 풀링 ON | 풀링 OFF |
|---|---|---|
| 프레임 타임 Median | 16.67 ms | 16.67 ms |
| 적이 스폰되는 프레임의 GC 할당 | **320 B** | **1.8 KB** |
| `Instantiate` 마커 | **없음** | 나타남 |

프레임 타임 차이는 관측되지 않았습니다. 실제 작업이 7~8 ms인데 예산이 16.6 ms라 애초에 여유가 있었기 때문입니다.
차이는 할당에서만 나타났고, 초당 할당률로 환산하면 19 KB/s 대 108 KB/s입니다.

측정 과정에서 찾은 것이 A/B 결과보다 컸습니다.
**프레임당 GC 할당의 90%가 디버그 로그였습니다** (3.1 KB → 320 B).
스킬 이펙트의 로그 플래그 기본값이 켜져 있어 빌드에서도 매 타격마다 문자열 보간과 스택 트레이스 캡처가 돌고 있었습니다.

> 판단의 근거와 나머지 시스템은 [기술 문서](https://app.notion.com/p/Core-Survival-3da9f5d1608b80eaa0cbd794c91e9f9c)에 있습니다.

## 코드에서 보기

경로는 `Assets/Scripts/Runtime/` 기준입니다.

| 보고 싶은 것 | 파일 |
|---|---|
| 오브젝트 풀 4종 | `Enemy/EnemyPooling` · `Skills/Effects/SkillEffectPooling` · `Combat/DamageTextPooling` · `Enemy/EnemyAttackPooling` |
| 스킬 로직과 이펙트 분리 | `Skills/SkillsBase` · `Skills/Effects/SkillEffectBase` |
| 데미지 계산과 치명타 | `Skills/SkillsBase`의 `CalcDamage` |
| ScriptableObject 데이터 설계 | `Skills/SkillDataSO` · `Progression/LevelUpOptionSO` |
| 레벨업 선택지와 리롤 | `UI/Panels/LevelUpPanel` |
| 게임 상태 머신 | `Core/GameManager` |
| UI 패널 다형성 | `UI/Panels/MenuPanelBase` |
| 데미지 인터페이스 | `Combat/IDamageable` |
| 적 AI (추적 · 겹침 방지 · 지면 스냅 · 공격 판정 · 근접/원거리) | `Enemy/TempEnemy` |
| 웨이브 스폰 | `Enemy/EnemySpawner` |

```
Assets/Scripts/Runtime/
├── Core/           게임 상태 머신, 카메라                        (2)
├── Combat/         데미지 인터페이스, 데미지 숫자와 그 풀         (3)
├── Player/         이동, 피격, 경험치, 적 스캐너                  (5)
├── Enemy/          적 AI, 웨이브 스포너, 적 풀, 투사체와 그 풀     (5)
├── Skills/         스킬 로직 5종, 스킬 매니저, 스킬 데이터 SO      (9)
│   └── Effects/    스킬 이펙트 5종, 이펙트 풀                     (7)
├── Progression/    레벨업 선택지 SO 상속 구조                     (5)
├── UI/             버튼 공통                                      (1)
│   ├── Panels/     일시정지, 결과, 레벨업 패널                    (6)
│   └── HUD/        체력, 경험치, 생존 시간, 스킬 슬롯             (4)
├── Audio/          BGM, UI 효과음, 볼륨 옵션                      (3)
└── SceneFlow/      씬 전환, 로딩                                  (6)
```

풀은 한 폴더에 모으지 않고 각 풀이 다루는 타입 옆에 뒀습니다. 풀과 그 대상은 함께 고쳐지기 때문입니다.

## 저장소 상태 — 클론해도 실행되지 않습니다

**외부 에셋 5종을 저장소에서 제외**했습니다.
코드와 씬은 전부 올라가 있지만, 클론하면 모델 · 이펙트 · 아이콘 · 맵이 비어 있어 게임이 동작하지 않습니다.

| 제외된 에셋 | 없으면 |
|---|---|
| `KayKit` | 플레이어와 적의 모델 · 애니메이션. 적 공격의 타격 시점인 Animation Event도 이 폴더의 `.fbx.meta`에 저장돼 있어 함께 빠집니다 |
| `Polygon Arsenal` | 스킬 이펙트 5종과 적 투사체의 원본 이펙트 |
| `Skill_Icon_Pack` | 스킬 아이콘 (선택지와 HUD가 빈칸) |
| `LowPolyFantasyArena2` | 아레나 맵 |
| `GUI Interface Kit Free` | UI 스킨 |

에디터 보조 도구(vFolders, vHierarchy)도 제외돼 있지만 게임 실행과는 관계없습니다.

**플레이해 보시려면 [빌드 다운로드](https://github.com/sinwa3/Core_Survival/releases/tag/v1.0.2)에서 받아 `Core_Survival.exe`를 실행하세요.**
로딩 바가 가득 찬 뒤 화면을 한 번 클릭해야 게임이 시작됩니다. 저장소는 코드를 읽는 용도로 봐주시기 바랍니다.

## 조작

| 키 | 동작 |
|---|---|
| **W A S D** / 방향키 | 이동 |
| **Space** | 대시 (쿨타임 1초) |
| **ESC** | 일시정지 — 플레이어 스탯과 스킬별 강화 현황 |

공격은 자동입니다. 시간이 지날수록 적이 더 많이, 더 강하게 몰려오고 1분 30초부터 원거리 적이 섞입니다.

## 알려진 제한

- 적이 지형을 통과할 수 있습니다. 평면 아레나를 기준으로 만들어 장애물 우회(NavMesh)를 넣지 않았습니다
- 미사일 발사음이 적중 시 끊깁니다. 소리를 이펙트 오브젝트의 수명에 묶은 구조 때문입니다
- 쿨타임 하한에 도달한 스킬도 쿨타임 강화 선택지에 계속 나옵니다. 골라도 수치는 더 줄지 않으며, 현재 쿨타임은 일시정지 화면에서 확인할 수 있습니다
